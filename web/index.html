Endpoint LLM → opencode / Hermes / dsh …

Sonde une API OpenAI-compatible (http://ip:port/v1) sur le réseau, puis écrit le fournisseur dans les fichiers de configuration des harnais détectés sur cette machine. La sonde passe par LLMBridge (pont local, aucune requête hors de l’endpoint que vous sondez) : c’est ce qui évite le blocage CORS qui rendait la version file:// inutilisable.
1 Détection des harnais
Interface servie par LLMBridge (pont local sur 127.0.0.1) : c’est le pont qui lit et écrit les fichiers sur le disque et qui interroge l’API — le navigateur ne peut ni l’un ni l’autre depuis une page file:// (pas d’accès disque, et CORS bloque Origin: null). Fichiers recherchés sous la racine scannée : .config/opencode/opencode.jsonc · .hermes/config.yaml (+ .hermes/.env) · .dsh/cordis.patch.yml (+ .dsh/.env). Chaque écriture laisse une sauvegarde .bak-<horodatage> à côté du fichier.
Aucune détection lancée.
